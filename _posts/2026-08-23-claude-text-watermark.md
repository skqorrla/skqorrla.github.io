## 워터마크가 왜 필요할까

LLM이 쓴 글과 사람이 쓴 글을 구분하는 일은 점점 어려워지고 있습니다. 문체를 보고 판단하는 탐지기는 모델이 바뀔 때마다 무너지기 때문에, 생성 단계에서 통계적인 흔적을 심어 두고 나중에 그 흔적만 확인하는 방식이 제안됐습니다.

핵심은 사람이 읽어서는 알 수 없지만, 키를 아는 쪽에서는 몇백 토큰만 있어도 높은 확신으로 판별할 수 있어야 한다는 점입니다.

> 💡 참고: 워터마크는 생성 단계에서 토큰 선택 확률을 아주 조금 비트는 방식이라, 사람이 읽어서는 차이를 느끼기 어렵습니다.

## 통계적 워터마크의 기본 아이디어

매 토큰을 생성할 때 직전 토큰을 시드로 어휘를 `green_list`와 `red_list`로 나누고, 그린 리스트 토큰의 로짓에 작은 보너스 δ를 더합니다. 그러면 워터마크가 있는 텍스트는 그린 토큰 비율이 우연보다 높아집니다.

### 그린 리스트와 레드 리스트

리스트를 나누는 기준은 비밀 키와 직전 토큰의 해시입니다. 같은 키를 가진 탐지기만 어떤 토큰이 그린이었는지 복원할 수 있고, 키가 없으면 텍스트는 평범한 문장으로만 보입니다. [Kirchenbauer 외 (2023)](https://arxiv.org/abs/2301.10226)의 설계가 이 계열의 출발점입니다.

### z-score로 탐지하기

탐지할 때는 같은 키로 리스트를 복원해 그린 토큰 수를 세고, 기대값 대비 얼마나 벗어났는지 z-score로 계산합니다. 아래는 그 계산을 요약한 코드입니다.

```python
import math

def score(tokens, key):
    hits = sum(t in green_list(key, prev) for prev, t in pairs(tokens))
    n = len(tokens)
    return (hits - 0.5 * n) / math.sqrt(0.25 * n)   # z-score
```

## 실험: 탐지율과 품질 저하

δ를 키울수록 탐지율은 오르지만 perplexity도 함께 오릅니다. 1k 토큰 기준으로 정리하면 다음과 같습니다.

| 설정 | 탐지율 (1k tokens) | 품질 (perplexity) |
|---|---|---|
| δ = 1.0 | 91% | +0.8 |
| δ = 2.0 | 99% | +2.1 |
| 워터마크 없음 | 4% (오탐) | 기준 |

## 정리와 한계

패러프레이즈나 번역을 거치면 흔적이 희석되고, 짧은 답변에서는 통계적 확신이 부족합니다. 그래도 생성 과정에 개입하는 방식은 모델이 바뀌어도 유지된다는 점에서 실용적입니다.

- 긴 텍스트일수록 탐지 확신이 높아진다
- 키가 유출되면 워터마크를 우회할 수 있다
- 품질 저하는 δ와 어휘 분할 비율로 조절한다
